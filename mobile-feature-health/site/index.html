What each column means

  • Unit tests · line coverage — share of the feature's executable lines that unit tests run. iOS: the unit-test-coverage.json (xccov) of the weekly Bitrise workflow firefox_unit_tests_ios_versions (latest Xcode, iOS 27 simulator), attributed to features with the taxonomy's feature map. Area rows include code attributed to the area alone; the "All" row is feature code only (shared code such as the browser shell is left out). Coverage says the code ran during a test, not that a test checks it: read it next to the escaped bugs. Known gap: xccov sometimes leaves out Swift packages it attributes to another binary (currently QuickAnswersKit and VPNKit), so features built on them, such as Quick answers and VPN, only count their app code for now. Click an iOS percentage to see the feature's files in the iOS unit test coverage tab. Android isn't measured yet.
  • UI automation · % of TestRail cases — share of the feature's TestRail Full Functional cases whose Automation field is Completed (XCUITest / Espresso). It's the TestRail status, not a verified run.
  • Manual · TestRail cases — number of Full Functional cases attributed to the feature, automated ones included.
  • Escaped bugs — bugs reported by people outside the team, created this year so far. Click a number to see them in the Escaped bugs tab, where they can be filtered, sorted and downloaded. iOS: firefox-ios GitHub issues with a bug label, author not an org member or collaborator, feature decided by hand. Android: Bugzilla Firefox for Android defects, reporter not @mozilla.com and not a bot, duplicates / invalid excluded, feature from the component (refined by title inside mixed components).

How cases are attributed

  • Every section of the Full Functional suites (iOS 45443, Android 3192) starts its description with a feature ID, e.g. LIB.BMK, or an area ID such as CRED. A case takes the ID of its section or of the nearest parent section that has one. IDs come from FEATURES.md; a daily check alerts on Slack when a section has none.
  • Area rows count every case in the area, including the ones attributed to the area alone, so they can be larger than the sum of their features.

Reading this tab

  • One section per feature, with the source files whose lines count for it, most uncovered lines first. Files that symbol rules split between features show up in each, with that feature's lines only.
  • Biggest gaps — the file's functions with the most lines no unit test runs (closures count in the function they're in), linked to the function in the code. They're where a test adds the most lines; whether it's worth testing is for the team to judge.
  • Files come from the same xccov report as the overview, so the same known gap applies: Swift packages xccov leaves out aren't listed. Shared code, excluded code and files not in the feature map are at the end.
